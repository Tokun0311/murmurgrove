# Phase 2.9 · Source Structure Reading

**Incremental patch over Phase 2.8. Not a new life-event engine or a recovered historical organism.**

## Intent

Give the dated, SHA-256-protected archive checkpoints created in Phase 2.8 a *spatial reading* without pretending that the checkpoint was an observed earlier organic state. It distinguishes:

1. **Archive source**: verified records and declared `METADATA_ONLY` references.
2. **Reference geometry**: the unchanged, pinned silent simulated T0 projection, which is not claimed as historically observed.
3. **Unlocated archive records**: newly verified records without a T0 position, counted and named, never assigned synthetic positions.
4. **Life events**: remain zero. No Writing activation, fibers, mature cores, or retrospective biological rewind are generated.

## Use

Open `OPEN-THREADS.cmd`, click **History → Archive versions**, select a sealed checkpoint, then click **在空间中阅读这一版本 ↗**. The source files are read and validated against their *raw byte* SHA-256 before the version is drawn. The source reading is a still, readable reference network. Close the small `SOURCE / ... ×` badge to return to the breathing organism. Visit traces remain available as before.

At the current state, there is only **one proven checkpoint**. It displays 174 nodes and 158 metadata relations because the sole checkpoint is the frozen current baseline. It is NOT an earlier time frame and there is no morphing between undocumented historical bodies.

For later author-confirmed checkpoints, the same reader:

- Can display a new **source-backed** metadata link if both endpoint IDs already have legitimate T0 positions, with a brighter optical line denoting an added declared reference.
- Can distinguish a newly added source record **with** a valid existing geometry ID, without activating it biologically.
- Does **not** draw records or links that have no legitimate reference coordinates. The badge counts the unplaced records and names the first two. The full source records are always preserved by the append-only chronicle from Phase 2.8.
- Can show removed/absent source records by omitting them from the read-only projected graph; it never rewrites T0 or the live organism.

This is an interpretive **source-structure layer**, not a source-generated historical T1/T2 snapshot, new plant tissue, or a capture of the archived organism on an earlier date.

## Installing on Windows

**Prerequisite:** Phase 2.8 is installed in the standalone experiment `experiments/murmurgrove-phase2-6/`.

1. Unzip this patch.
2. Merge its `experiments` folder into the **inner repository root** `C:\Users\deng\Desktop\tow-archive\tow-archive\`.
3. Allow overwrite of precisely these preexisting files:
   - `experiments/murmurgrove-phase2-6/public/index.html`
   - `experiments/murmurgrove-phase2-6/public/viewer.mjs`
   - `experiments/murmurgrove-phase2-6/public/version-chronicle.mjs`
4. Newly installed files:
   - `public/source-structure.mjs`
   - `tests/source-structure.test.mjs`
   - `README-2.9.md`
5. Run the **existing** `OPEN-THREADS.cmd`; optionally run the existing `VERIFY-THREADS.cmd`.

This patch does **not** contain or change archive data, chronicle index, sealed source checkpoint files, scripts, cmd openers, personal TOW ARCHIVE website code, or any previous experiment's files.

## Continuing toward *real* morphology history

A genuine reconstructable past body requires an immutable, time-stamped *render or morphology state* derived from verified author activity at the time, with exact geometry/dynamics parameters, appropriate provenance, and a separately approved life-event log. No such historical states are currently available. Future work may add that recording pipeline, but this phase makes no claim that the current reference geometry constitutes historic anatomy.
