# Murmurgrove Phase 2.6 · Archive Threads (read-only)

## Goal
Return to the original **extremely fine filament / airy points / low-chrome UI** while using the **actual TOW ARCHIVE relation graph**. This is a **runnable Canvas 2D browser sandbox**, not a rendered concept image or a website deployment.

## To run (Windows)
1. Place `experiments/murmurgrove-phase2-6` inside the actual `tow-archive` git root.
2. Double-click `OPEN-THREADS.cmd`.
3. Visit `http://127.0.0.1:4186/` in a desktop or mobile-sized browser. For a phone on the same LAN, a local proxy/tunnel would be needed because this sandbox intentionally binds only to `127.0.0.1`; no public deployment is made.

## Source integrity / ethical boundaries
- This package contains **byte-identical original** `known-data-baseline.v1.json`, `navigation.json`, `T0.json`, `manifest.json` from previously pinned Phase 1B.4/Phase 2 snapshot inputs.
- Baseline contains 181 included records; 7 quarantined; 174 eligible for view. 158 non-quarantined metadata-only references become **exactly 158 thin evidence lines**; there are **20 isolated records** with no invented connections. The main declared connected component is 123 nodes.
- Every line corresponds to an actual source `navigation.metadataLinks` reference. **Metadata links never become active life fibers automatically**.
- Actual authored life events were zero at the locked baseline. Consequently **there are ZERO actual Writing tension roots, ZERO mature propulsion cores, and ZERO activated life fibers**. The elaborate synthetic `T1/T2` visual scenarios in earlier Phase 2 sandboxes are intentionally NOT used. This may appear quieter than the decorative conceptual illustrations, and that is correct.
- The frozen `T0` position seed originates in the Phase 1B.4 reference calibration. **It is not evidence of a true historical bodily shape**. Only the archive identities, declared references and recorded visit dates are verified.
- Exhibition amber glow uses `amplitude=exp(-elapsed calendar days/13)` at a record's genuine `occurredOn` date. This is an explicitly **display-only observational trace**, NOT a `life.encounter` author assertion, and never threshold-eligible work or a propulsion-core trigger. No extra show/encounter is created.
- The visual Growth view emphasizes **observational age of exhibitions and existing metadata links**. It must not be misread as validated physiological lignification history, which is unavailable without author events.
- Movement draws a display-only deterministic Gaussian-neighborhood deformation and local optical micro-particles, **not new relations or actual event-driven metabolic flow**. Inactive links remain optically faint.
- The Phase1B.4 physiological parameters remain unchanged: digestion τ=13d, metabolic cap=2.6, refractory period=45d. This standalone UI does **not** replay Phase1B.4 on author logs, because there are no author-verified activation events to replay and inferring their ingestion times would fabricate history.
- Live TOW ARCHIVE pages, `.md` records and author event logs are **never edited**.

## Interaction
- Whole: all source-backed records + faint metadata evidence, plus derived optical density of real nodes.
- Growth: shows aged observation/deposition emphasis with smoke-gray-brown tones, **not invented Writing roots**.
- Movement: emphasizes reversible, local Gaussian-neighborhood display waves and dated exhibitions' amber pulses. No false life events.
- Click/tap a node to open a small anchored card; click the card title to open the real `tow-archive.pages.dev` record page. Browser Back restores mode, orbit, zoom and selection in the original tab via `sessionStorage` / page cache.
- At 200–1000%, a small card-corner locator dot displays the selected record's approximate location in the overall body. It can reset to whole view.
- Drag or touch to orbit the 3D-seeded node distribution, wheel/pinch/+/- to zoom. Bottom UI uses original Whole / Growth / Movement + History / zoom/info structure.
- Header menu or ⓘ opens the provenance panel.

## Limitations
- Does NOT claim exact cross-device synchronized phase motion. It uses each device's UTC clock.
- Mobile 60 FPS is **a performance target, not verified across all mobile devices**. Measure with a physical device before deployment. Canvas2D has bounded density particles rather than expensive all-pairs per-frame computations.
- Actual route availability is not verified against the public website; links are from the pinned navigation map, which is source-backed.
- No fake links, draft Writing activation, retrospective life-event dates or local archive writes.
